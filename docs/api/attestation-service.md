# Attestation Service Contract

## Status and Authority

This F0 contract publishes the Attestation Service as a standalone sub-system within AEGIVELA. The service issues and verifies compact EdDSA JWS attestation artifacts that bind artifact identity, signer identity, workload identity, and environment claims to a tenant-scoped principal. Verification requires all assertion groups to be present; partial attestations are rejected. The service never stores raw bearer tokens, credentials, unrestricted tool arguments, or raw sensitive payloads in metadata records.

Each artifact is a compact EdDSA JWS. The protected header contains exactly `alg: "EdDSA"` and the configured `kid`. The payload accepts no unknown or duplicate JSON members. Consumers must reject any other algorithm, an unknown key ID, an invalid signature, malformed claims, an invalid time window, an unexpected issuer or audience, or an artifact longer than 8192 bytes.

## Key Domain

The API process requires an independent attestation signing configuration:

| Environment variable | Purpose |
| --- | --- |
| `AEGIVELA_ATTESTATION_SIGNING_KEY_FILE` | Path to exactly one PEM-encoded PKCS#8 Ed25519 private key. |
| `AEGIVELA_ATTESTATION_SIGNING_KEY_ID` | Public key identifier placed in `kid`. |
| `AEGIVELA_ATTESTATION_ISSUER` | Issuer placed in `iss` and required by verifiers. |

These values are separate from `AEGIVELA_POLICY_DECISION_SIGNING_KEY_FILE`, `AEGIVELA_EXECUTION_GRANT_SIGNING_KEY_FILE`, and their companion variables. An attestation signing key must not be reused as a decision-signing or execution-grant key.

`GET /v1/attestations/jwks` returns the active attestation verification key as a public-only JWK Set. The JWK uses `kty: "OKP"`, `crv: "Ed25519"`, `use: "sig"`, `alg: "EdDSA"`, the configured `kid`, and base64url public coordinate `x`. It never returns private key material. This endpoint does not require authentication.

## Issuance Endpoint

`POST /v1/attestations/issue` is internally authenticated with exactly one valid `X-Aegivela-Internal-Token` header. The request body is:

```json
{
  "bearer_token": "<enterprise-oidc-bearer-token>",
  "artifact_digest": "<64-char-lowercase-hex>",
  "artifact_ref": {"kind": "gateway:backend", "id": "backend-1", "version": "v1"},
  "signer_identity": "build-system:v1",
  "signer_public_key": "<base64url-32-byte-public-key>",
  "workload_id": "workload-1",
  "workload_evidence": {
    "pairs": [{"key": "runner", "value": "github-actions"}]
  },
  "environment_claims": [
    {"key": "os", "value": "ubuntu-22.04"}
  ],
  "audience": "policy-evaluator",
  "policy_version": "policy-v1",
  "trace_id": "trace-1"
}
```

### Request Validation

All four assertion groups must be present:

| Group | Fields |
| --- | --- |
| Artifact | `artifact_digest` (64 lowercase hex chars), `artifact_ref` (`kind`, `id`, optional `version`) |
| Signer | `signer_identity` (bounded identifier), `signer_public_key` (base64url 32-byte Ed25519 public key) |
| Workload | `workload_id` (bounded identifier), `workload_evidence` (1-8 key-value pairs) |
| Environment | `environment_claims` (1-16 key-value pairs) |

`bearer_token`, `audience`, `policy_version`, and `trace_id` are required. All identifier fields are bounded to 256 characters with a restricted character set (`[a-zA-Z0-9\-._:/]`). Evidence and environment claim values allow spaces in addition.

Unknown fields, trailing content, or a body exceeding 1 MiB are `400 invalid_attestation_request`. The request body must not include `tenant_id`, `subject_ref`, or `issuer`; these fields are derived from the resolved identity and server configuration respectively and are rejected as unknown fields.

### Identity Binding

The `bearer_token` is resolved through the configured Identity Bridge. The resolved principal provides `tenant_id` and `subject_ref`. An expired principal identity is `403 attestation_denied`. An unauthenticated bearer token is `401 unauthenticated`. An unavailable identity provider is `503 identity_unavailable`.

### Response

On success the endpoint returns `201`:

```json
{
  "signed_artifact": "<compact-jws>",
  "jti": "<unique-jti>"
}
```

The signed artifact contains a JTI auto-generated by the server. The artifact validity window is one hour from issuance.

Missing or invalid internal authentication is `401 unauthenticated`. An unavailable signer, identity resolver, or metadata store is `503 attestation_unavailable`.

## Verification Endpoint

`POST /v1/attestations/verify` is internally authenticated with exactly one valid `X-Aegivela-Internal-Token` header. The request body is:

```json
{
  "signed_artifact": "<compact-jws>",
  "issuer": "aegivela:attestation",
  "audience": "policy-evaluator"
}
```

Unknown fields, trailing content, or an invalid request are `400 invalid_attestation_verify_request`.

The verifier validates the compact JWS signature, protected header, claims, and time window. It rejects:

- Malformed tokens, wrong algorithms, unknown key IDs
- Invalid or expired time windows (nbf/iat/exp)
- Missing assertion groups (all four must be present: artifact, signer, workload, environment)
- Mismatched issuer or audience
- Corrupted signatures, duplicate JSON members, unexpected payload keys

Invalid signatures, malformed artifacts, or expired artifacts are `401 unauthenticated`. A verified artifact that is revoked is `403 attestation_denied`. An unavailable verifier is `503 attestation_unavailable`. Missing or invalid internal authentication is `401 unauthenticated`.

On success, the endpoint returns `200` with the verified attestation claims.

## Error Summary

| Condition | Status | Code |
| --- | --- | --- |
| Missing or invalid internal token | 401 | `unauthenticated` |
| Invalid bearer token identity | 401 | `unauthenticated` |
| Malformed or expired attestation artifact | 401 | `unauthenticated` |
| Expired principal identity | 403 | `attestation_denied` |
| Revoked attestation | 403 | `attestation_denied` |
| Invalid request body | 400 | `invalid_attestation_request` or `invalid_attestation_verify_request` |
| Body too large | 413 | `request_too_large` |
| Unavailable signer, verifier, identity, or store | 503 | `attestation_unavailable` or `identity_unavailable` |

## Consumer Rules

Consumers must fetch or configure only the attestation public key through the JWKS endpoint, validate all artifact and binding requirements, and fail closed when verification is unavailable. A consumer must not override tenant identity, subject reference, or attestation issuer from the HTTP request body. An unsigned attestation has no authority for policy decisions.
